# ZUK-3254 implementation receipt

## Authorized behavior

Publish a content-free `@zukantech/agent` bootstrap that admits a consumer only
after its authenticated GitHub identity proves access to the private producer.
Verify immutable producer evidence before creating repository-scoped,
cross-harness workflow links. Preserve all existing consumer policy and harness
configuration, and roll back partial writes.

## Red evidence

The first focused run failed because `src/install.mjs` did not exist. The
security expansion then failed for missing GitHub, doctor, and CLI modules; for
unrequired workflow/executable payload roots; and for incomplete rollback.
The rollback case proved an especially important defect: cleanup removed a
pre-existing empty `.claude/` directory. The implementation now snapshots
parent existence before mutation and removes only installer-created paths.

## Green evidence

- `node --test`
- `npm run validate`
- `npm pack --dry-run --json`
- install the generated tarball in an empty temporary prefix and invoke its
  `zukan-agent` binary
- exercise the production GitHub adapter against an authenticated `gh` session
  with private producer access

Final focused result: 20/20 tests passed. The public tarball contains 12 files,
the package scanner found no protected paths or credential-shaped content, the
installed binary returned its expected usage/doctor errors, live authorization
succeeded without returning protected content, and `npm audit` reported zero
known vulnerabilities.

The final fixed point and independent review result are recorded before PR
publication.
