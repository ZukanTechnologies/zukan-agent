# ZUK-3254 implementation receipt

## Authorized behavior

Publish a content-free `@zukantech/agent` bootstrap that admits a consumer only
after its authenticated GitHub identity proves access to the private producer.
Verify immutable producer evidence before creating repository-scoped,
cross-harness workflow links. Preserve all existing consumer policy and harness
configuration, and roll back partial writes.

## Red evidence

The first focused run failed because `src/install.mjs` did not exist. The
security expansion then failed for missing GitHub, doctor, and CLI modules; for
unrequired workflow/executable payload roots; and for incomplete rollback.
The rollback case proved an especially important defect: cleanup removed a
pre-existing empty `.claude/` directory. The implementation now snapshots
parent existence before mutation and removes only installer-created paths.

## Green evidence

- `node --test`
- `npm run validate`
- `npm pack --dry-run --json`
- install the generated tarball in an empty temporary prefix and invoke its
  `zukan-agent` binary
- exercise the production GitHub adapter against an authenticated `gh` session
  with private producer access

Final focused result: 27/27 tests passed. The public tarball contains 12 files,
the package scanner found no protected paths or credential-shaped content, the
installed binary returned its expected usage/doctor errors, live authorization
succeeded without returning protected content, and `npm audit` reported zero
known vulnerabilities.

The final fixed point and independent review result are recorded before PR
publication.

## Independent review

Review at `1a9173c` found two P1 gaps: doctor trusted only mutable local state,
and mutation had no cooperative serialization around ancestor revalidation.
The correction persists the signed manifest and Sigstore bundle, makes doctor
re-authorize through GitHub and re-verify signature, producer, tag, revision,
and installed bytes, and adds an exclusive repository mutation lock with
repeated ancestor validation. Regression tests cover coherent local forgery,
revoked GitHub access, moved tags, and concurrent-installer admission.

Re-review at `9150e2c` found that an unclean process exit could strand the
cooperative lock. The final protocol uses an atomically created lock directory
with host, boot epoch, PID, start time, and nonce metadata. Live owners block;
dead, rebooted, malformed, and cross-host states remain untouched and fail with
explicit inspection/removal guidance. A live PID always blocks regardless of
age; the protocol never invites removal of a verifiably active installer.

Confirmation review at `60c7247` found no remaining actionable issue in the
live-owner correction. Its read-only sandbox could not create test fixtures;
the authoritative local run immediately before publication passed 27/27 tests,
package validation, archive inventory, and the npm advisory gate.
