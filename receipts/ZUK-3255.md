# ZUK-3255 implementation receipt

## Authorized behavior

Extend the verified public bootstrap with deliberate local updates, explicit
release rollback, a non-failing stable-release warning cached for at most 24
hours, and an opt-in `--pr` publisher. No branch, commit, push, or pull request
may occur without `--pr`; publication may contain only installer-owned output.

## Red evidence

The first focused `npm test` run passed the inherited bootstrap suite but failed
six new entry points: the CLI did not recognize `update`, doctor emitted no
advisory warning, and the update-cache, update transaction, and publisher
modules did not exist. Those failures were preserved before implementation.

Threat-model iterations added regression cases for cache write failure,
consumer ignore rules, stale or divergent default branches, obsolete skills,
signature rejection, transactional link rollback, and reuse of a retained
release during an explicit rollback.

## Material choices

- Successful update metadata is cached outside the repository for 24 hours and
  keyed by repository path plus installed release. Network, cache-read, and
  cache-write failures suppress only the advisory notice.
- Updates re-prove the current pin, verify the selected release through the same
  GitHub/Sigstore contract as installation, retain immutable historical vendor
  and evidence trees, and transactionally switch the lock and harness links.
- Rollback may reuse a retained tree only after its evidence bytes and complete
  file inventory match the newly downloaded, signed release.
- `--pr` requires a clean local default branch exactly matching the freshly
  fetched remote default branch. It observes ignored installer output,
  force-adds only declared installer-owned paths, compares the staged and
  committed path sets, rechecks the worktree after hooks, and pushes only then.

## Green evidence

- `npm test`
- `npm run validate`
- `git diff --check`
- `node --check` on changed executable modules
- packed-artifact installation and binary smoke test
- `npm audit --audit-level=high`

Current focused result: 46/46 tests pass and the public package validator finds
16 package files with no protected path or credential-shaped content. The exact
`0.1.0-alpha.2` tarball installed into a clean prefix and its binary returned the
sanitized expected usage error. `npm audit --audit-level=high` reported zero
known vulnerabilities. The fixed point and independent review evidence will be
appended before PR publication.

## Independent review

Review of fixed point `57beb21` found one low-severity documentation mismatch:
the README said default install/update performed a separate cached advisory
lookup, while the implementation deliberately avoids resolving latest twice.
The correction now states that default install/update resolve latest exactly
once, while doctor and explicit pin/rollback operations use the advisory cache.
No runtime correctness, security, rollback, or publication-boundary finding was
reported.

Re-review after the documentation correction found one high-severity
publication issue: path-set equality alone could not detect a pre-commit hook
replacing bytes inside an allowed path. The correction snapshots the complete
staged Git tree and requires the post-hook commit tree to have the identical
object ID before push. A regression fixture proves hook-modified bytes never
reach the push step.
